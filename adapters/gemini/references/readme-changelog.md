# README / Changelog Reference

Use this reference when the user needs repository-level orientation or release notes.

## README Purpose

A README should tell a newcomer what the project is, how to use it, and where to look next.

## README Recommended Structure

1. Title and one-line summary
2. Visual or short positioning statement
3. Why it exists
4. What it does
5. How to get started
6. Core usage
7. Repo structure or key links
8. Contribution or maintenance notes

## Changelog Purpose

A changelog should summarize user-visible changes and notable fixes over time.

## Changelog Recommended Structure

1. Version or date
2. Added
3. Changed
4. Fixed
5. Removed
6. Notes or migration guidance

## Writing Rules

- README should reduce onboarding time.
- Changelog should be scannable and release-oriented.
- Use concise bullets and clear versioning.
- Avoid implementation dump unless it matters to users.

## Quality Check

- A newcomer should know what the project is within a minute.
- A returning user should quickly find what changed.
